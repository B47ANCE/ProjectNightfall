## Current implementation

Project Nightfall owns sunlight hibernation, starvation-gated Feral conversion,
Smart and Alpha Feral policy, artificial-UV damage, effigy reactions, and Alpha
ecology. Project M.O.R.T.I.S. supplies identity, hunger observations, hierarchy,
memory, logical groups, and bounded runtime infrastructure. lightWorks supplies
emission facts; medWorks supplies severed-part provenance.

The Alpha ecology currently includes persistent hierarchy, rivalry, desertion,
Death Cry power vacuums, underground territories, distributed Smart dens,
light suppression, prey reports, probable-base evidence, artificial-UV emergency
displacement, pressure/season-gated physical migration initiation, and persisted
temporary daylight shelter objectives for multi-night journeys.

lightWorks 0.24 now exposes active dropped emitters through the real Build 42
physical thump contract. Existing den-defense and rare independent-attack policy
consume that provider without transferring zombie behavior into lightWorks.

The regional UV pipeline now owns configurable artificial-only canonical tissue
loss after real clothing transmission. An emitter-bounded, budgeted and fair
corpse runtime restores copied M.O.R.T.I.S. anatomy, avoids darkness backfill,
continues protected postmortem loss, and persists monotonic semantic remains
stages without replacing the corpse, changing its cause or clearing loot.

The requested artificial-UV tile-strength change is currently blocked by a
request/source mismatch: authoritative source already sums established
attenuated, obstruction-checked contributions at the target tile and feeds that
total directly into regional dose, while the referenced flat direct-damage path
exists only in stale staging backups. See
[the tile-strength handoff](ARTIFICIAL_UV_TILE_STRENGTH_HANDOFF.md) before making
any production change.

## Release gates

- Complete live calibration of the active clothing-aware, per-anatomical-region
  UV score and persistent Project M.O.R.T.I.S. wound pipeline. The same stored
  regional score now powers eligible Feral behavior; the obsolete global
  `uvPoints` reserve and both legacy direct-health damage paths are removed.
- Validate both Nightfall presets in the new-game UI.
- Stress very-high population through sunset, rise, dawn, and save/reload.
- Verify true fake-dead hibernation, clothing retention, health floors, hunger
  eligibility, transformation, and night recovery.
- Validate light color, range, occlusion, stacking, portable/world lamps, and
  artificial-UV wound progression and terminal remains behavior.
- Validate effigies, crowd flow, Smart groups, Alpha calls, dens, emergency
  displacement, rivalry, and loaded physical migration.
- Complete hosted and dedicated-server authority and persistence testing before
  claiming multiplayer compatibility.

## Approved post-release research additions

- **EXT-27 — Definition-driven conditions:** create a first-party registry shape
  for eligibility, acquisition, stages, scheduled transitions, treatment/cure
  capabilities, persistence version, public observations, and presentation
  events. Start with one Nightfall-owned condition and prove replay, migration,
  offline elapsed time, treatment races, and multiplayer authority. Faded
  Afflictions content and balance are not included. The current pipeline, bounded
  transaction contract, proof matrix, and exact sequencing blocker are recorded
  in `CONDITION_SYSTEM_EXT27.md`. Implementation remains deferred until the
  existing Nightfall release gates pass and a specific first-party condition plus
  canonical treatment capability are approved.
- **Project Remnants exclusion:** do not detect, adapt, integrate, or claim
  compatibility with Project Remnants through MORTIS or any other API.
- **EXT-32 — Survivor history consumer:** optionally consume experienceWorks
  memorial/history records for investigations or narrative after their owning
  schema exists. Do not create records implicitly.

These additions cannot delay the current release gates or alter existing UV,
Feral, remains, smoke, persistence, or networking semantics.
